# /experimentation

To make an uncertain thing clear, run a small experiment.

## Principles

1. **Run the smallest useful test.** Keep it cheap and narrow enough to learn
   before making a large commitment. When several paths look possible, give
   each a small test instead of betting everything on one.
2. **Make the test easy to stop or undo.** Set the loss you can afford before
   starting. Prefer an action you can stop, reverse, or redirect if it goes
   badly.
3. **Say what would change the decision.** Before testing, name the result that
   would lead you to continue, change course, or stop. Also set a point where
   the test ends without a clear answer.
4. **Act on what you learn.** Let the result change the decision. Record
   surprises and harm, make no claim stronger than the result, and repeat only
   when another test could add useful information.
5. **Do not test when action cannot help.** Use thinking or existing evidence
   when they can settle the question. Do not test when there is no time to
   learn or the choice is one-shot and all-or-nothing. For whether to wait or
   commit, use `optionality`.
6. **Do not pass the risk to others.** A cheap test for you may be costly for
   someone else. Do not make other people carry harm they did not choose.

## Workflow

Name the uncertainty and the decision it affects. Choose the smallest
reversible test, set the affordable loss and decision rules, run it, then act.

## Checklist

Uncertainty; decision; small test; cost; reversibility; stop point; possible
results; effect on others; action after the result.

## Anti-patterns

Testing what thought can settle; betting too much; deciding the rule after the
result; ignoring a result; making other people absorb the downside.

## Output

State the uncertainty, test, limit, stop point, result-to-decision rules, who
bears the risk, and how the result changed the decision.
