# /idea-quality

The domain of judging whether an idea is good. Judge an idea by what it is
and where it came from. These principles hold for any idea in any field;
whoever runs this says which apply.

## Principles

1. **A good idea is a good pattern: a real problem that keeps recurring,
   plus the core of its solution, where first principles (its basic parts,
   causes and costs) explain the mechanism by which that solution works.**
   The rest follows from this:
   - It fails if it rests only on popularity, "it is like X", "others do it",
     or someone's say-so.
   - One problem plus one mechanism makes one cohesive idea. If it cannot be
     stated as one problem and one mechanism in a sentence, it is a bundle:
     judge each idea in it on its own.
   - The author's own need is evidence that the problem is real. That
     evidence needs no proof, but the recurring problem must be named.
   - Where its design choices are written down, each should follow from the
     problem and say what it gives up. If they are not written down, do not
     count that against it.

## Definitions

- **Use / value underneath:** what a person does with it, and the lasting
  problem it solves, whatever the tool. What is new is how it attacks that
  problem.
- **What is new:** the usual approach's bottleneck (its cost when known), the
  one move that removes or bypasses it, and whether that is a new way or the
  same way faster. Not its results. The same way faster is labelled faster,
  not new; it matters only when the speed-up changes what people can do.
