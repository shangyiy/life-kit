# /way-outs

The use case for taking a risk because you could fall back. Every principle of
[`investing`](../../core/investing/SKILL.md) applies unchanged; this skill adds
two checks, the first with a counting rule. Use it to make the decision or to
review one; in a review, name each breach once, with its fix.

## Checks

1. **Is the way out real?** A fallback is the path you name to catch you if
   the risk hits. It is a way out only if it passes all four tests:
   - Named holder: you can say who or what catches you.
   - Stated terms: you can say under what conditions it does.
   - Lasts: it will still exist until the risk could hit; an earlier last
     date fails.
   - There when needed: it does not fail in the same event as the risk.

   If a fact a test needs is missing, ask once. If it stays missing, or you
   cannot ask, that test fails. Take stated facts as given and do not re-check
   them, unless they conflict with each other or with other evidence.

   Verdict: a fallback that fails any test is a claim, not a way out. One that
   passes all four is real, and that verdict does not wait on more checks.

   Next: name what using it costs and what it leaves uncovered, without
   lowering the verdict. Count only the fallbacks that pass, each only up to
   the part of the risk it covers. If none passes, decide as if there were no
   way out (`investing` 1).
2. **Is the option decaying?** Apply it to a way out that passed check 1. An
   option is a choice you hold now: that way out or the chance it backs. Ask
   whether its value shrinks the longer you wait, what it would be worth if
   used later, and its last date, the one from the Lasts test, not a second
   test. If it shrinks, waiting has a cost (`investing` 5). If it holds, there
   is no hurry exactly while the last date lies beyond the time you need to
   decide. Decay is a reason to decide, and deciding includes declining. It
   never replaces check 1.
